# 改动前拷问（plan-interrogation）

## 零、这个技能解决什么

AI 最贵的失败不是 bug，是**做完才发现解的是另一个问题**。

根因很朴素：你说两三句话，AI 热情地替你把五个没定的决策都定了，然后照着错的假设写 250 行。

本技能把「动手前」这段对话强制成一次面试。方法论改造自 Matt Pocock 的 `grill-me`（MIT），**提问清单换成本项目的硬约束红线**——通用技能不会问你「这个文件会不会破 99 行」「退出码断言怎么写」，而这些在你项目里才是真正卡死的东西。

一句话判据：**没复述完整份计划并获你确认之前，一行代码都不写。**

---

## 一、四条铁规（来自 grill-me，原样保留）

1. **把计划当成决策树，不是文档。** 先找「其他决定都挂在它上面」的根决策；父决策定了再问子决策——上游答案会改变下游什么值得问。
2. **一次只问一个问题。** 问完停下，等回答。Q2 的答案常常取决于 Q1，一次性抛出一串问题会把你按在组合空间里。
3. **每问必须附自己的推荐答案 + 一句理由。** 你只做判断题：确认 / 推翻 / 改方向。**只提问不给推荐答案视为违规**（纯苏格拉底式空问会把人问死）。
4. **能自己查的不许问你。** 见第四节。事实是 AI 的活，判断题才是你的活。

---

## 二、先静默分级（不问用户，先自己查）

不搞一视同仁的六十连问——那会把小改动拖成负担。先读代码与文档判定等级，再决定拷问深度：

| 等级 | 判据 | 拷问深度 |
|---|---|---|
| **L0 局部** | 单文件内改动，不碰包边界 / 流水线阶段语义 | 2–4 问，只问边界与验证 |
| **L1 模块内** | 跨文件、改包内部结构，不改对外行为 | 4–8 问 |
| **L2+ 架构** | 碰包边界（ast / frontend / backend / error）/ 公共类接口 / 产物格式（COFF / PE） | 第三节全清单逐条过 |

分级依据自己查：`docs/0003-RustJ编译器.md`、`docs/0004-RustJ二期实现.md`、`git log`。

## 三、本项目专属提问清单

L2+ 全过；L1 只挑相关条目；L0 只留 3.4 与 3.5。**每一条如果答案在代码里，先去查再决定要不要问。**

### 3.1 洁癖

- 改动涉及的文件会不会破 **99 行**（≤99）？破了按哪个语义单文件拆、还是开新子包？
- 是否守住**一 class 一文件、类与文件名统一小写**？
- 新增文件的包归属对不对（ast 只存数据、frontend 只管词法语法、backend 只管机器码与产物）？
- 新增公开类有没有写好 **Why 型注释**（解释设计理由，不是复述代码）？

### 3.2 架构

- 依赖方向对不对：`frontend → ast`、`backend → ast`，两者互不引用；`error` 独立成包供前后端**单向**依赖——会不会引入**环**？
- 后端是否仍面向 `arch` 抽象接口？新指令/新架构是否只动 `arch` 的实现类，前端与 AST 零改动？
- 标号回填职责是否仍归 `codebuffer`（不许让 `x64` 膨胀破 99 行）？
- AST 是否仍是**纯数据**（不含任何机器码逻辑）？

### 3.3 产物与语言子集

- 碰不碰 COFF / PE 产物格式或 `main.java` 对外入口（`java -jar RustJ.jar <源文件.rs>`）？碰了属**不兼容变更**，README 快速开始要不要同步？
- 新语言特性进不进当前子集边界（`fn` + i32 + `let`/赋值 + 算术比较 + `if/else`/`while`/`return`）？越界特性要不要先扩分期计划再动手？

### 3.4 测试与验证

- 验证命令是哪几条？
  `javac -d build -sourcepath Code Code\main.java` → `jar cfe RustJ.jar main -C build .` → `java -jar RustJ.jar Code/examples/<用例>.rs` → 运行 `RustJ/out/<函数名>.exe` 断言 `ERRORLEVEL`
- 每个新特性有没有配套 `examples/*.rs` **退出码断言用例**（如 `fn main() -> i32 { 42 }` 运行后 ERRORLEVEL 必须为 42）？
- `examples/` 既有用例（min 期望 0、arith 期望 7、ops 期望 7、flow 期望 55）是否全部不回归？

### 3.5 版本号

- RustJ **不绑定游戏版本号**，采用独立语义版本：不兼容变更（入口参数 / 产物格式）`y+1`，加性 / 修复 `z+1`。
- 是否要标**预发布**？

## 四、什么时候不许问（先去查）

以下信息一律自己查，**不许拿它当问题消耗用户时间**：

| 要查的 | 去哪查 |
|---|---|
| 已有约定与写法 | 读相邻同类文件 |
| 分期路线与进度 | `docs/0003-RustJ编译器.md` + `docs/0004-RustJ二期实现.md` |
| 验收用例与期望退出码 | `Code/examples/` |
| 编译与验证的正确姿势 | README〈快速开始〉 |

查完仍不确定的，**把查到的事实带进问题**再问：
> 「README 写的是 X，代码里是 Y，以哪个为准？」

---

## 五、收尾：复述 → 确认 → 才动手

决策树关完（每个未决项要么已定、要么你明确说「执行时再定」、要么明确出界）后，**停下来**，把整份计划复述给你：

1. 本次要做的事（一句话）
2. 已定的决策清单（逐条，含接受的取舍）
3. **明确不做什么**（逐条——最容易跳过，也最关键）
4. 改动面（哪些文件 / 包 / 产物格式）
5. 验证命令（含退出码断言）
6. 版本号判断

等你确认后才开工。**确认前不动手**，包括「顺手先建个文件」这类小动作。

---

## 六、反模式（踩了即违规）

- 一次抛多个问题（「lexer 怎么改？codegen 呢？PE 呢？」）
- 只提问，不给推荐答案
- 问一个自己能从仓库里查到的事实
- 没问完就动手，或边问边改
- 跳过「明确不做什么」
- 对 L0 小改动也上全套拷问
- 越界：提交/推送/发布交给 `compliant-delivery`
